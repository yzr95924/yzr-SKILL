# 对外行为审视点

> 评估故障时对外行为是否合理的参考，支撑可疑点判断；按分析对象分节，
> 审视点按故障维度标注；新审视点追加到对应对象末尾，跨对象的进“通用”

## 通用

- 部分成功、部分失败时，向上返回的错误码明确且各处一致
- 异步接口 callee 不重复 callback，或 caller 能正确处理
- caller / callee 资源分配与释放一致，不泄露不重复分配

## 函数/接口调用

- 通用：外部接口都有错误处理，caller / callee 双方一致；重试策略匹配，
  callee 支持重入或幂等；失败重试不过频，避免 CPU 消耗或大量资源待回收
- 返回失败：事务 abort 有效回退，无资源残留或状态遗漏；错误码向上层转换
  保留“可否重试”语义；失败对资源回收与故障切换的影响
- 超时：callee 不访问 caller 已释放的空间；上游超时后下发的取消 / 中止命令有处理
- 内容错误：数据处理结果支持错误校验，错误时可旁路
- 系统环境：复位后接管业务无耗时操作；因复位 / 掉电终止的配置类命令
  （创建、删除、修改）可重入；时间跳变不影响时间戳机制与定时任务

## 消息通信

- 返回失败：失败上抛策略明确——哪些失败对上游可见、哪些内部消化，
  内部故障不扩散为业务中断
- 超时：状态机与资源管理支持重入；能识别无效消息（如时间戳）；
  状态机迁移能处理超时或意外到达的消息
- 内容错误：传输校验关键点有效，校验失败处理符合设计
- 系统环境：“对端已生效但应答丢失”时 caller 重试、callee 幂等；
  节点复位导致的跨节点请求失败不直接扩散为对上游的失败

## 资源访问

- 通用：资源分级与预留——关键路径用高优先级资源，普通路径不挤占；
  资源占用（内存、目录等）不超限，可回收或隔离；处理路径上的队列有超时 / 清理机制；
  资源严重不足有回收与逃生通道；预留充分，支持配置类流程重试
- 返回失败：向上失败还是重试策略明确；申请失败避免死等，防资源死锁；
  资源不足有识别与过载控制；失败资源纳入泄露管控、可由自愈等机制回收；
  申请不到避免就地重试，返回合适重试点；预留资源纳入健康监控
- 超时：等待锁等超时返回后无资源泄露
- 部分失败：部分对象失败不拥塞整个流程
- 系统环境：资源已分配但流程未结束时故障 / 掉电，有释放与回收路径

## 数据与配置访问

- 通用：批量数据获取有限量保护；数据拷贝有错误检查与容错，
  评估并发冲突及中途故障 / 掉电的处理；删除或释放的资源延迟复用，便于误操作恢复
- 返回失败：修复策略（重试、换路、降级读写等）本身不引入一致性问题；
  元数据故障与附加功能隔离
- 超时：返回慢时有 QoS / 流控保证
- 内容错误（SDE 静默数据错误）：各环节（介质、内存、链路、处理）有校验手段
  发现静默数据错误；校验失败时不得把错误数据返回给用户 / 上游——可经冗余副本、
  重试换路等修复后正常返回，无法修复时返回明确错误并记录日志告警，不静默放行；
  数据有效性校验（校验和、地址范围、父子关系等）及修复策略；
  存储空间使用前初始化，避免脏数据误读；配置信息有校验机制，能判定读取失败
- 部分失败：多副本 / 冗余写入的一致性策略明确（强一致或多数派），
  冗余度不足时有处理
- 系统环境：failover / 上下电时元数据状态标识与序号设置正确，旧数据不误判为有效；
  部分数据已持久化时复位 / 掉电，重启后数据一致、无资源泄露；
  事务写入或回滚中途复位 / 掉电，不产生不一致或泄露

## 共享状态

- 通用：只读状态或只读接口的处理明确；全局状态无并发冲突
- 系统环境：关键状态已改变但流程未结束时故障 / 掉电，能正确处理避免状态不一致；
  failover / failback 时内存对象状态与参数设置正确
