# 冗余度规则（redundancy）

砍掉的每个字都必须不损失信息。适用：啰嗦、注水、同一个意思说了两遍。
目标是**字数降下来、信息一克不少**——不是把文章改短，是把水挤掉。

## R1 同义重述

同一个观点换一种说法再讲一遍（AI 最常见的注水手法）→ 保留信息量大的那版。

- 前：这个方案风险很高。换句话说，采用这个方案可能让整个项目陷入不可控的境地。
- 后：这个方案风险很高，可能让整个项目失控。
- 识别信号："换句话说 / 也就是说 / in other words / that is to say"后面跟的如果
  不比前面多信息，删。

## R2 填充句

删掉后段落意思完全不变的句子 → 删。

- "这是一个非常重要的话题。" / "这个问题值得我们关注。" / "It is important to note that…"
- 判断法：把句子删掉读一遍——读者没损失，就是填充句。

## R3 过度限定词

非常 / 极其 / 相当 / 十分 / 真的 / really / very / extremely / quite——削弱而非加强。
默认删；只有限定词本身承载对比信息时保留（"极快"相对"快"是实测差异时）。

- 前：这个方案非常有效。→ 后：这个方案有效。（更好：给数据，"把延迟降到 50ms"）

## R4 注水开头结尾

- 开头模板："在当今……的时代 / 随着……的不断发展 / In today's fast-paced world" → 删，从正题起笔
- 结尾模板："总而言之 / 综上所述 / In conclusion"后跟全文复述 → 删；
  有行动项则改成一句行动号召（"下一步先跑基准测试"）

## R5 同义堆叠

两个及以上近义词并列当盾用 → 留一个。

- "帮助和协助" → 帮助；"改进和优化" → 优化（按语境选准的那个）
- "each and every" → each；"first and foremost" → first；"tips and tricks" → tips

## R6 中文"的"链与"是……的"

- "的"连用 3 次以上 → 拆或删："系统的配置的管理的界面" → "系统配置管理界面"
- "是……的"强调结构非必要 → 删："这个方案是可以落地的" → "这个方案可以落地"
- "进行 / 做出 / 给予" 类空动词见 style.md S6

## R7 英文功能词冗余

- "in order to" → "to"；"due to the fact that" → "because"；"at this point in time" → "now"
- "that" 不消除歧义时可删："I think that this works" → "I think this works"
- "There is / There are" 开头重写主语："There are three options that we support" →
  "We support three options"

## R8 过度举例

"例如 A、B、C、D、E、F"列一长串 → 保留 2–3 个最有代表性的。
例外：清单本身是交付物（API 列表 / 错误码表）时不动。

## R9 摘要与正文互注水

摘要段把正文每节复述一遍 + 正文里又有"本节将介绍……"预告 → 二选一：

- 短文档（< 1500 字）：删摘要 / 预告，正文自解释
- 长文档：摘要只留"为什么 + 结论"，删细节复述
