# 语气规则（tone）

语气 = 作者对读者的姿态。适用：太谄媚、太生硬、太营销、正式度与文体不符。
**只调姿态，不改立场**——原文的自信程度是作者的选择，除非它明显越界成吹嘘或自我贬低。

## T1 正式度匹配文体

先判文体，再定正式度基准，全文向基准收敛：

| 文体 | 基准 | 典型越界 |
| --- | --- | --- |
| 技术文档 / RFC | 冷静、陈述句、无感叹号 | "超好用！"、"nb" |
| wiki 笔记 | 半正式，允许第一人称思考痕迹 | 过度客套（"敬请指正"） |
| 邮件 / 汇报 | 礼貌但直接 | 开头三段寒暄不进正题 |
| 对外公告 | 正式、克制 | 网络用语、emoji |

## T2 去谄媚

- 删对话式捧场开头："Great question!" / "好问题！" / "这是一个非常好的想法"
- 删过度感谢与道歉："非常感谢您的耐心等待"在非客服语境 → 删
- 删自我贬抑铺垫："我才疏学浅，以下只是抛砖引玉" → 直接给内容
- 例外：邮件真实社交语境里的礼貌用语保留（那是写给真人看的）

## T3 去营销腔

技术内容里出现广告词 → 换成可验证的说法。

- "业界领先 / 极致性能 / 完美解决 / revolutionary / cutting-edge / seamlessly" →
  给事实："P99 延迟 50ms" / "兼容 99% 的现有配置"
- 感叹号在技术文档全文 ≤ 1 个

## T4 人称一致

- 中文全文统一"你"或"您"，不混用；技术文档默认"你"
- 英文统一 "you"（指南）或 "we"（团队决策记录），不跳
- 中英都不要"你 / 我们 / 大家 / 咱们"随机轮换

## T5 中英语气差异

同一种语气在两种语言里实现方式不同，改写时用目标语言的惯例，不做字面对译：

- 英文偏好直接祈使句开头（"Run the tests"），中文同场景更自然是陈述句（"先跑测试"）
- 中文的"请"高频出现会显得客服腔；技术文档里能省则省（"请参考"→"见"）
- 英文敬语（"Please kindly…"）在非正式文档里删掉不损失礼貌

## T6 对冲节制

hedging（"可能 / 也许 / 在一定程度上 / might / perhaps / somewhat"）连用是 AI 的不自信腔：

- 一句里 ≤ 1 个对冲词；一段里 ≤ 2 个
- 作者确有依据的不确定保留对冲，并尽量写明依据（"可能——还没在生产验证过"）
- 对冲三连（"可能在某种程度上或许"）→ 留一个

## T7 命令式与建议式的分寸

- 文档给读者的指令：直接祈使句（"运行 X"），不要"你可能想要考虑运行 X"
- 文档表达作者主张：陈述句 + 依据（"我们选 A，因为……"），不要"我觉得也许 A 会好一点吧"
- 对上级 / 对外场景：保留协商式语气（"建议……"），不改强硬
