# 重构 + 合理性审视规则清单(SSOT)

同一处代码命中多条规则: 按最贴根因的一条报,连带症状写进该条建议,不拆成两条
子项标签: 报 / 不报 列命中例与豁免;反向 列逆向操作;注意 列护栏

## 重构规则

- **命名与签名**: 名不表意 / 同概念多处叫法 / 缩写 / 单字母滥用;函数名与行为不一致;参数含混 / 顺序别扭,调用方加注释解释
  - 不报: 同名不同义不合并;API 已发布留向后兼容
- **函数粒度**: 函数 > 30 行或内嵌多个语义段(注释 / 空行分隔),抽具名函数;
  表达式难读(链式调用 / 跨越 ≥ 3 个子表达式)或同表达式 ≥ 2 处,用具名局部变量,带逻辑则抽函数
  - 反向: 函数体与名字一样清晰 / 过度包装则内联;变量名无新信息 / 仅用一次,直接用表达式
  - 不报: 广泛调用但各调用处语境不同的不内联;名字误导时改名而非内联
- **参数与接口**: 参数簇 ≥ 3 个函数出现或列表 > 5 个 / ≥ 4 个常同现,封装成结构 / 数据类(来自既有对象的
  Preserve Whole Object 复用,需新建聚合概念才封装新对象);bool / enum 控制分支,拆具名函数;
  近似函数仅字面量有差异,合并 + 差异提参数;参数可由其他参数 / 上下文算出,删;query 有副作用拆 query + command
  - 不报: 测试桩 / API 兼容语义的参数保留
- **职责与归属**: 类 ≥ 3 个独立职责,拆类;类只剩 1-2 个方法且少被引用,并回;函数 / 字段多数行为依赖另一个类,搬过去;
  两个子类同方法体 Pull Up,父类方法只被一个子类用 Push Down,构造公共段同样 Pull Up;
  委托链穿透(`a.b.c.field`)加委托方法;一半方法都是无增值委托,删中间层
  - 注意: 被广泛引用的先 Move 再谈并回;跨模块搬移注意导入方向;public 字段先封装再搬
- **数据封装**: 可变数据被外部无约束读写 / 记录结构直接暴露,用访问器 / 类封装,必要时加访问控制;
  基本类型承载业务含义且同值多形式散落,引入值对象 + 格式校验;
  字段可由其他字段算出,删字段改 getter
  - 注意: 派生字段与源字段的同步失配
- **条件逻辑**: 条件嵌套 ≥ 3 层 / 循环嵌套 ≥ 2 层 / 嵌套三元,抽具名函数;多个条件返回同一结果或 ≥ 3 个条件用同一处理,合并单路径;
  异常 / 边界嵌套、正常路径埋在 else 深处,反转 early return;类型 switch ≥ 3 分支,搬子类多态;
  同一特殊值(null / undefined / 特定枚举)检查散落,引入特殊值对象
- **死代码**: 从未被调用的变量 / 函数 / 类、被注释掉的代码块、走不到的分支,删
  - 注意: 公共 API 出口先确认无外部调用;git history 留着

## 合理性审视

- **边界与校验**: 外部输入(用户输入 / API 参数 / 文件内容 / 环境变量)直接进核心逻辑、信任边界无校验,
  入口校验(类型 / 范围 / 非空 / 格式) + 非法输入快速失败
  - 不报: 内部调用已有校验的不重复
- **错误处理**: 空 except / 忽略错误返回值 / 错误只 log 后继续 / 裸 catch-all,至少记录错误上下文,无法处理时向上传播或显式降级;
  同模块混用返回值 + 异常 + 错误码,统一传递机制,跨边界转换集中管理
- **魔法值**: 裸字面量(数字 / 字符串)承载业务含义 / 同一值多处重复(多形式散落同值归数据封装),用具名常量 / 枚举;业务配置项走配置
- **计算经济性**: 无界 / 大数据集上的嵌套循环、可提前退出却全量扫描、列表反复 `in` 查找,换数据结构 / 算法降档;
  循环内重复调外部资源(N+1)、循环不变量重复计算、昂贵结果多处重算,批量取数 / 提循环不变量 / 缓存;
  复杂度不变仅更清晰等价实现的走 Replace Algorithm,逐步替换 + 测试覆盖
  - 不报: 数据规模与热路径未确认前不报;仅理论更优 / 冷路径可不报
- **重复代码**: 相同 / 近似块(结构同、仅字面量 / 变量名不同)重复即报,跨文件同算;抽公共函数 / 方法,差异点参数化;改 A 必改 B 的成对结构也算
  - 不报: 仅 2 处且 ≤ 5 行的短小块;语义各自独立演化的巧合相似;单行字面量重复归魔法值
- **注释**: 默认多余,存在即自证: 说不清"删掉会踩什么坑"的即发现项
  - 报: 与代码矛盾 / 描述已删旧行为;复述 what;结构 / 流程叙述(该由代码自描述);段头横幅;docstring 复读签名;解释改动过程
  - 不报: 仅 why / 非显然约束 / 外部契约三类;矛盾以代码为准改注释(代码确是 bug 则改代码)
  - 注意: 解释性叙述先问能否用代码表达(改名 / 抽函数),能则改代码 + 删注释;删前查没藏魔数来源 / 坑成因,有则提炼成一句 why
