# 写入 capture 的执行细节

> 本文件承载[章节](../SKILL.md#写入-capture)的全部执行细节

## 寻址

MEMORY/ 只认 git root 一份（从 cwd 向上找 `.git`；非 git 目录用项目根）；找不到时转 init 入口，不就地散写。submodule / 子目录不建 MEMORY/

## 五道闸（agent 自主写入的准入）

垃圾记忆的真正来源是无人逐条把关的自主写入，五道闸全过才提：

1. **证据绑定**：候选必须指向本轮具体事件（哪次纠正、哪个坑、用户哪句"以后都"）；无证据 = 感想，不提
2. **负清单**：一律不收。能从代码 / git 推导的事实；AGENTS.md / 文档已写的；操作步骤与任务经过；知识性结论（归 wiki）；某 skill 自身的用法与踩坑（改该 skill 源）
3. **自检**："删了这条，下个会话会做错决定吗？"不会就不提
4. **作用域**：写得出约束对象（目录 / 文件 / 决策点）才提；空泛到写不出 scope 的候选就是垃圾
5. **合并优先**：先查索引，同主题已有条目则并入更新（刷新 modified），禁止新增第二条

## 落点路由

| 内容形态 | 落点 |
| --- | --- |
| 一句话事实 | 索引行（行格式 SSOT 见 `assets/memory-index-template.md`） |
| 需要展开为什么 / 边界 / 证据 | `<slug>.md` 条目（骨架见 `assets/memory-entry-template.md`） |
| 跨项目偏好 / 本机专属 / 不宜入库 | agent 私有记忆（host 各自的落点），项目仓库内不写 |

写入顺序：**先写条目文件，再挂索引行**——中断只留孤儿（audit 可查），不留死链（更糟）

## 确认与落盘

- 列表提议，每条标：内容一句话、落点、证据；用户确认后按序写入
- 宁缺毋滥：一轮提议 0~3 条，0 条是合法输出
- 写前查预算水位（以 lint 输出为准）：报 `INDEX-BUDGET-HIGH` 时先给精简案再写入；报 `INDEX-BUDGET`（ERROR）时转 audit 入口精简、回来再写
- 落盘后交付说明提示：未 commit 前其他 worktree / 协作者看不到

## 批量沉淀（会话末）

触发："把这轮收获整理进记忆 / 沉淀一下"。流程 = 从本轮提取候选 → 五道闸逐条过 → 列表提议（每条含落点）→ 一次确认 → 按序写入。任何一条被否不影响其余
