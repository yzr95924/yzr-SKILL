## 输入与输出

- **输入**：capture 收本轮会话的纠正 / 约定 / 踩坑（用户点名或 agent 提取）；audit / init 收项目根
- **输出**：capture 交付落盘的条目 / 短条目；audit 交付体检报告与逐条确认后的治理动作；init 交付 MEMORY/ 骨架与 AGENTS.md 引用段

## 执行原则

- **决策依据不是日志**：只收"删了它，下个会话会做错决定"的内容
- **先提议后落盘**：写入与删除都先出提案，用户点头才动文件
- **合并优先**：同主题永远只有一条，并入更新而非新增
- **吸收即删**：条目内容进了文档 / 代码 / AGENTS.md，条目本体就删（git 可恢复）
- **索引有顶**：索引常驻上下文，故设数值硬门限：写入前先比行数与字节数、达阈值即拦截，不依赖自觉；预算数值与水位规则以 `assets/memory-index-template.md` 为 SSOT
- **落点红线**：项目内容只进项目 MEMORY/；密钥 / token / 对人的评价永不入记忆：密钥泄露无法回收，对人的评价会固化进后续会话的判断

## 工作流

先归类再动手：写入走[章节](#写入-capture)，体检 / 清理走[章节](#治理-audit)，无 MEMORY/ 要建体系走[章节](#初始化-init)。
查询（"记忆里有没有 X"）不走流程：索引能答就答，需要细节才读条目正文；未命中明说、不编

### 写入 capture

闸的是 **agent 自主写入**（批量沉淀、主动提议）；用户点名的单条"记一下"，人是闸门，本流程只补合并检查与落点 / 格式判断。先 Read `ref/capture-workflow.md` 再动手（四道闸、落点路由、写入顺序、批量节）

### 治理 audit

安全网，兜住写入闸门漏掉的腐化。先 Read `ref/audit-workflow.md` 再动手（机械层跑 lint、判断层事件驱动复核、三级阶梯治理、体检数字报告）

### 初始化 init

不主动推销；用户点名、或 capture 发现无落点时才提议。先 Read `ref/init-workflow.md` 再动手（骨架创建、AGENTS.md 引用段）
