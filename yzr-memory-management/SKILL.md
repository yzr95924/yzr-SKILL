## 输入与输出

- 写入收本轮会话的纠正 / 约定 / 踩坑；清理 / 初始化收项目根

## 执行原则

- **决策依据不是日志**：只收“删了它，下个会话会做错决定”的内容
- **只写规则本身**：条目与索引行是指导执行的陈述句，不写成事件记录。证据只在提议时出示，不落盘；日期以 git log 为准；一条一个规则，正面直陈（X 一律 Y）
- **先提议后写入**：自主写入与删除先出提案，用户点头才动文件；用户点名的单条写入免提案，合并、位置、格式判断进交付说明
- **合并优先**：同主题永远只有一条，并入更新而非新增
- **不成双源**：条目内容进了文档 / 代码 / AGENTS.md，条目本体就删（git 可恢复）；可预见频繁更新的结论（版本 / 当前值 / 进行中状态）从一开始就不收，各持一份必烂
- **作用域**：每条记忆写得出约束对象（目录 / 文件 / 决策点），写不出的不收
- **索引有上限**：索引常驻上下文，所以行数和字节数有硬上限；上限数值以 `assets/memory-index-template.md` 为准
- **禁写**：项目内容只进项目 MEMORY/；密钥 / token / 对人的评价永不入记忆。密钥泄露无法回收，对人的评价会固化进后续会话的判断

## 工作流

先归类再动手：写入走[章节](#写入)，体检 / 清理走[章节](#清理)，无 MEMORY/ 要建体系走[章节](#初始化)。
查询（“记忆里有没有 X”）不走流程：索引能答就答，需要细节才读条目正文；未命中明说、不编

### 写入

检查针对的是 **agent 自主写入**（批量沉淀、主动提议）；用户点名的单条“记一下”由用户本人把关，本流程只补合并检查与位置 / 格式判断。先 Read `ref/capture.md` 再动手

### 清理

先 Read `ref/audit.md` 再动手

### 初始化

不主动推销；用户点名、或写入流程发现项目还没有 MEMORY/ 时才提议。先 Read `ref/init.md` 再动手
