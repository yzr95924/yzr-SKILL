# yzr-memory-management

防记忆腐化与膨胀：写入有门、删除有路、索引有顶

## 入口

先归类，再动手；执行细节见[章节](#工作流)各入口

1. **写入 capture**：把会话收获（单条或批量）沉淀为记忆条目
2. **治理 audit**：体检 MEMORY/ 并清理（过期 / 被吸收 / 矛盾 / 重复 / 超预算）
3. **初始化 init**：为无记忆约定的项目建立 MEMORY/ 体系

查询（"记忆里有没有 X"）不走入口流程：索引能答就答，需要细节才 Read 正文；未命中明说、不编

## 输入与输出

| 入口 | 输入 | 输出 |
| --- | --- | --- |
| capture | 会话中的纠正 / 踩坑 / 约定（用户点名或 agent 提取） | 经确认落盘的条目文件 / 索引行 |
| audit | 项目根（含 MEMORY/） | 体检报告（机械检查 + 治理候选）+ 逐条确认后的治理动作 |
| init | 项目根（无 MEMORY/） | 经确认创建的 MEMORY/ 骨架 + AGENTS.md 引用段 |

## 执行原则

1. **记忆是决策依据不是日志**：只收"删了它，下个会话会做错决定"的内容；操作步骤、任务经过、能从代码 / 文档推出的东西一律不收
2. **先提议后落盘，删除必确认**：写入与删除都先出提案，用户点头才动文件
3. **合并优先**：同主题永远只有一条，并入更新而非新增
4. **吸收即删**：条目内容进了文档 / 代码 / AGENTS.md，条目本体就删（git 可恢复）
5. **索引有顶**：常驻面（自动加载的索引）上唯一写入前拦截的算术级闸，不依赖自觉——预算数值与水位规则以 `assets/memory-index-template.md` 为 SSOT
6. **落点红线**：项目内容只进项目 MEMORY/；agent 私有记忆只放跨项目偏好，最多存指针；密钥 / token / 对人的评价永不入记忆

## 工作流

### 写入 capture

闸的是 **agent 自主写入**（批量沉淀、主动提议）；用户点名的单条"记一下"，人是闸门，本流程只补合并检查与落点 / 格式判断。先 Read `ref/capture-workflow.md` 再动手（五道闸、落点路由、写入顺序、批量节）

### 治理 audit

安全网，兜住写入闸门漏掉的腐化。先 Read `ref/audit-workflow.md` 再动手（机械层跑 lint、判断层事件驱动复核、三级阶梯治理、体检数字报告）

### 初始化 init

不主动推销；用户点名、或 capture 发现无落点时才提议。先 Read `ref/init-workflow.md` 再动手（骨架内容、AGENTS.md 引用段）

## 参考样例

会话末用户说"把这轮的收获整理进记忆"：agent 在 git root 找到 `MEMORY/`，从本轮提取候选并
逐条过五道闸："包管理用 uv"（证据：用户纠正过 npm 用法；落点：索引行）、"金额一律
Decimal"（证据：用户明确约定；落点：索引行）、"orders/ 有上游校验"（负清单命中：能从代码
读出，不收）——列表提议 2 条，用户确认后追加到 `MEMORY/MEMORY.md` 末尾；交付说明提示
未 commit 前其他 worktree 看不到
