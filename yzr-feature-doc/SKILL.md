name: yzr-feature-doc
description: |
  为具体功能或特性编写、更新或审计设计文档、实现方案、测试报告、SFMEA 分析文档、trace 分析文档、灰度方案与决策日志。
  当用户提到功能设计、实现方案、测试用例、故障模式分析、SFMEA、trace 分析、灰度上线或记录技术决策，并要求落成文档时使用。
  不适用：PRD、API 参考文档、README、wiki 归档、项目记忆，或只要代码实现 / 口头分析。
---

## 输入与输出

- 输入：文档类型、目标文档或对应材料；SFMEA 需要已实现代码、配置、可检索的 UT/ST 用例或已有分析材料；类型不明时先问
- 输出：新建或更新一份 Markdown 文档，未指定路径时写入当前目录；审计在对话中报告问题与修改建议，不改原文件
- 决策日志：追加到指定文件；未指定时使用 `decision-log.md`

## 执行原则

- 只完成目标文档所需的分析、写作与审计，包括代码、配置、用例和 trace 审视；不做独立技术评审，也不执行实现、测试、上线或故障处置
- 新建和更新文档严格逐章输出：每次只写一个二级章节并交用户确认，
  确认后再写下一章；不因用户要求一次性完成而合并输出
- 章节形状和顺序以对应模板为准；生成、更新、审计和复核遵循对应类型指导；
  模板说明不复制进产物
- 带“更新时间”的文档，新建或更新时刷新为当天日期
- 按模板与类型指导检查遗漏：明确不适用或确定没有才写“无”，材料未提及或缺信息写“待确认”，不擅自补默认决策
- 事实、推断和建议分开写；推断标注依据与验证方式
- 关联文档只链接不复制；正文中文，技术术语保留英文

## 工作流

1. 判断文档类型与操作（新建 / 更新 / 审计），类型不明时先问
2. 按文档类型读取对应指导文档，再读其中链接的模板：
   - 设计：`ref/design.md`
   - 实现：`ref/implementation.md`
   - 测试报告：`ref/test-report.md`
   - SFMEA：`ref/sfmea.md`
   - trace 分析：`ref/trace-analysis.md`
   - 灰度：`ref/rollout.md`
   - 决策日志：`ref/decision-log.md`
3. 新建 / 更新：
   - 阅读用户材料与既有文档，区分事实、推断和待确认项；
     成文前加载 yzr-writing-style（未安装则忽略）
   - 新建按模板与类型指导成文，更新只改用户要求的部分
4. 审计：对照模板、类型指导与执行原则逐节检查章节结构、提示项回应、“无 / 待确认”用法、
   事实与推断、术语与数字；既有“无”无反证时不报问题，有反证才指出并给依据；
   在对话中报告原文位置、问题和修改建议，全部符合时明说通过，不改原文件
5. 交付前复核：新建和更新按模板、类型指导与执行原则复核；更新确认未误改其他内容
