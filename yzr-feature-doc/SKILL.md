name: yzr-feature-doc
description: |
  为具体功能或特性编写、更新或审计设计文档、实现方案、测试文档、trace 分析文档、灰度方案与决策日志。
  当用户提到功能设计、实现方案、测试用例、trace 分析、灰度上线或记录技术决策，并要求落成文档时使用。
  不适用：PRD、API 参考文档、README、wiki 归档、项目记忆，或只要代码实现 / 口头分析。
---

## 输入与输出

- 输入：文档类型、目标文档或对应材料；类型不明时先问
- 输出：新建或更新一份 Markdown 文档，未指定路径时写入当前目录；审计在对话中报告问题与修改建议，不改原文件
- 决策日志：追加到指定文件；未指定时使用 `decision-log.md`

## 执行原则

- 只负责文档写作与审计，不做技术评审，也不执行实现、测试、上线或故障处置
- 章节、顺序和表达以对应模板为准；模板说明不复制进产物
- 新建或更新多章节文档时，默认逐章讨论并确认；用户明确要求一次性完成时除外
- 按模板提示检查遗漏：明确不适用或确定没有才写“无”，材料未提及或缺信息写“待确认”，不擅自补默认决策
- 事实、推断和建议分开写；推断标注依据与验证方式
- 关联文档只链接不复制；正文中文，技术术语保留英文

## 工作流

1. 判断文档类型和操作（新建 / 更新 / 审计），读取对应模板：设计 `assets/template-design.md`，实现
   `assets/template-implementation.md`，测试 `assets/template-test.md`，trace 分析
   `assets/template-trace-analysis.md`，灰度 `assets/template-rollout.md`，决策日志
   `assets/template-decision-log.md`
2. 新建或更新：阅读用户材料与既有文档，区分事实、推断和待确认项；
   成文前加载 yzr-writing-style（未安装则忽略）；
   新建按模板成文，更新只改用户要求的部分，决策日志只追加
3. 审计：对照模板与执行原则逐节检查章节结构、提示项回应、“无 / 待确认”用法、
   事实与推断、术语与数字；在对话中报告原文位置、问题和修改建议，
   全部符合时明说通过，不改原文件
4. 交付前复核：新建和更新按模板与执行原则复核；更新确认未误改其他内容
