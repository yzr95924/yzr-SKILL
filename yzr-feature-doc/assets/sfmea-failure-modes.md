# 故障模式清单

> 分析代码时逐条对照的检查清单。
> 维护：新条目追加到对应类别末尾，格式为“名称：一句话说明”，与既有条目同类时合并优先于新增；
> 新类别在文末加 H2 节，并附一行适用导引。

## 函数/接口调用

流程中调用其他模块或服务接口时对照。

- 返回失败：调用复杂模块接口时，可能会失败（如对方会访问硬盘或网络）
- 超时：调用复杂模块接口时，可能会长时间不回响应
- 静默失败：故障已发生但无任何报错、告警或状态变化，调用方误以为成功，
  如异常被吞、操作未生效却返回成功

## 资源访问

流程中申请内存、锁、配额等资源时对照。

- 申请资源失败：内存、配额等资源全部被使用时，新的申请可能会失败
- 申请资源超时：申请锁资源等场景，如果被其它执行流占用，可能会阻塞当前申请，直到对方释放
- 申请资源超规格：大业务量冲击等场景下，内外部并发请求数超过系统设计规格

## 数据与配置访问

流程中读写数据或配置时对照。

- 数据读取失败：数据读取失败，要求容错处理
- 数据只读：例如文件系统为只读状态
- 配置读取失败：例如缓存的配置故障，或本机配置被破坏
- 返回的数据被破坏（SDE，静默数据错误）：物理介质（如盘、接口卡缓存）或内存中的数据
  出现静默错误，如 bit 跳变、写或读偏；经链路转发的数据出现静态失效
- 数据处理结果错误：拷贝、转换、压缩、运算等处理结果出错但无报错，如拷贝偏移、
  源数据已变化；调用方拿到错误数据而不自知

## 消息通信

流程中跨进程 / 跨节点收发消息时对照。

- 消息发送失败：受网络影响可能导致消息未发送到对端或者被丢弃；进程故障导致跨节点消息发送失败
- 收到重复消息：受网络影响可能导致收到请求方重复发送的消息
- 通讯中数据被破坏：受网络影响，导致传输的关键消息头或是数据出现跳变
- 应答超时：受网络或对端性能影响可能导致响应消息在指定时间后返回；进程故障导致不响应

## 并发与批量操作

流程中同时操作多个对象或批量处理时对照。

- 群发消息部分失败：同时向多个节点发送消息，部分成功、部分失败
- 部分接口返回失败：并发访问多个下游时部分出错、部分响应慢
  （如同时向多块盘读/写数据，部分报错、部分返回慢）
- 局部数据访问失败：如批量数据删除、读取等操作时，能忽略错误部分并给出提示，不中断整体操作

## 共享状态与共享资源

流程中持有共享锁、占用共享配额或读写全局状态时对照。

- 占用共享锁的时长：评估持有共享资源（如共享锁）的时长，避免阻塞其他流程
- 占用共享资源量：评估占有共享资源（如内存页面、配额）的数量，避免影响或阻塞其他流程
- 依赖全局状态变量：评估全局状态变量在流程过程发生变化时对流程的影响

## 系统环境

所有流程都要对照：复位、掉电、时间跳变与流程动作无关。

- 节点复位：流程执行中断，关注数据完整性、重启后如何恢复执行等
- 进程复位：流程执行中断，包括正在执行的主流程中断、正在执行子流程的进程复位导致子流程中断、
  从而返回主流程失败；关注进程重启后如何重试、是否支持重入、事件是否丢失、数据完整性等
- 系统掉电：所有节点执行中断，关注数据完整性、重启后如何恢复执行等
- 系统时间跳变：涉及与时间相关的操作，如时间戳等都需要关注时间变化对自己的影响

## 进程生命周期

所有流程都要对照，尤其是常驻进程与后台任务；拉起、开工、异常状态类故障先看进程管理 / 自愈框架是否已统一处理。

- 进程复位后拉起失败：进程复位后拉起过程失败，如初始化执行失败
- 进程复位后拉起超时：进程复位后拉起过程初始化执行超时
- 进程复位后开工失败：进程初始化成功，开工流程失败
- 进程复位后开工超时：进程初始化成功，开工流程超时
- 进程持续处于异常状态：进程长时间处于非正常运行态
- 进程持续处于 D/Z 状态：D 状态是不可打断过程的正常保护，应该很短暂，长期存在说明挂死；
  Z 状态长期存在说明进程不能退出
- 与进程间心跳中断
- 进程频繁复位

## 外部依赖

流程依赖网络、存储设备或接入部件时按依赖类型对照。

### 网络链路

- 链路中断 / 闪断 / 误码 / 拥塞 / 单通
- 多链路间性能显著差异

### 存储设备

- 设备整体掉电及掉电恢复
- 设备连接中断
- 设备热插拔：设备拔出、插入；插入规格不匹配或其它型号的设备；
  冗余重建等关键过程中设备被快速拔出
- 设备挂死，无响应
- 设备性能劣化：如慢盘
- 介质错误：坏块、误码
- 容量变化：如设备缩容
- 单设备 / 多设备故障：尤其多设备同时故障对冗余度的影响

### 接入部件 / 服务

- 监听端口被占用
- 连接数耗尽

外部依赖的详细故障场景以对应组件方维护的清单为准，此处只列通用类别。
