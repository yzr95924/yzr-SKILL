# 原则校验的完整流程

> 本文件承载[入口 4](../SKILL.md#原则校验)的执行细节

## 步骤

1. **机械项**：`python -m tools.verify <skill-dir> --tier <default|reference|meta>`（tier 按目标 skill 类型：`reference` 型（纯参考资料：只聚合信息、不改变行为决策）、`meta` 型（元 / 多入口）、其余 `default`）
2. **全量精读不抽样**：目标 skill 的 `SKILL.md` + `ref/` + `tools/` + `assets/` + `eval/` 每个文件逐行读，对照本 skill 的执行原则与本文件判定清单 → 逐项给结论（结果词见判定清单），证据 = 文件 + 原文引用
3. **报告只活在对话里**：不建 `audit-*.md` 归档文件（无人维护的第二真源）；逐项等用户确认；报告分两小节：违反项（按清单 / 原则）与待删候选（按保留门槛逐节扫，无则写"无"）

> 用户要求"最严 / 仔细审查"时：正确性以验证证据为准（无证据不断言）；修复只动仓库源，不手拷 vendored 副本

## 判定清单

机械项之后的逐条判定口径（脚本覆盖的项出候选与证据，是否违反照此判；结果词五档：通过 / 违反 / WARN / 标注 / 忽略）：

1. **agent 中立**：点名具体 agent（Claude Code / Qoder / Cursor 等）逐处复核：特有机制设计（该 agent 独有功能）通过；可泛化却写死 → 违反，改泛指
2. **触发语不回正文**：正文逐句问"管何时调还是怎么用"；何时调内容（触发语 / 路由结论）出现在正文 → 违反，触发负例归 `description`"不适用"槽；闸门 / 纪律句在执行点的重述不算
3. **指标单一来源**：同 skill 内同一 `<数字><单位>` 散落多文件 → 违反；定权威源，其余改常量名或指针引用
4. **机械操作归脚本**：每段文字过"能用脚本钉死吗"；零判断字节操作仍以文字承载 → 违反（应脚本化）；md 重述脚本机制细节 → 违反（机制挪脚本）；纯函数但不值脚本成本（低频 / 一行命令可代 / 判定全靠人）→ 违反（过度固化）
5. **依赖单向**：skill 间依赖必须 DAG；互提候选对，人工判方向，双向依赖 → 违反
6. **跨 skill 指称**：单向提及（路由指针 / 题材点名）越过 skill 名指对方内部路径 / 节名 / 组名 → 违反，停在 skill 名或删；真实功能依赖显式保留
7. **相对路径禁止**：markdown 链接只指本 skill 目录内；跨 skill 相对链接 → 违反（会因对方重构无声断裂），需要时用纯文本"X 侧规范 §Y"描述
8. **参考文件禁手写目录**：参考文件内手写目录 → 违反；agent 全量读入不看目录，目录只对浏览器 / 编辑器有效
9. **纪律内容须有据**：纪律型 / 模式型内容无 baseline / eval 痕迹 → 标注"未经验证"，审计者不凭精读断言对错
10. **保留门槛**：存量内容逐节逐段问：它服务的失败 / 场景能否溯源（自体声明的动机、git blame、evals）；不能且非结构必需（路由 / 闸门 / 槽位）→ 标注"待删候选"，只标不删、用户裁定；实删转入口 2，有 evals 时跑回归，不回归即实证
11. **长度**：超软目标 → WARN 偏臃肿；超 `BODY_WORD_LIMIT` → 违反
12. **时间性信息不内联**：自身演进史（版本记录 / 修复日志）内联 → 违反，演进史归 git
13. **节名契约**：规范节名 / 顺序以 `assets/skill-template.md` 为准；`BODY-SECTION-MISSING` WARN 按已知债忽略

## 审查分工

本清单与机械项只管**机制合规**：md 散文质量归 yzr-writing-review，`tools/` 代码审查归 yzr-coding-review，`description` 触发质量归入口 3（有独立评估机制），各自转交
