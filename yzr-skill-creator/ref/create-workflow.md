# 创建一个 skill 的完整流程

> 本文件承载[入口 1](../SKILL.md#创建一个-skill)的全部执行细节

## 第 1 步：意图识别与访谈

当前对话可能已包含要沉淀的工作流（如"把这段流程沉淀成 skill"）。若是，先从对话历史抽取答案：用到的工具、步骤顺序、用户做过的修正、观察到的输入输出格式；再主动补齐缺口。需要确认：

1. 这个 skill 应该让 agent 能做什么
2. 什么时机触发（什么样的用户表述 / 上下文）
3. 期望的输出格式
4. 边界情况、示例文件、成功标准、依赖项
5. 流程每步标注**判断 / 机械**：机械 = 零判断、可枚举，默认进 `tools/` 规划；留 md 的到第 3 步记录理由

调研：检查可用 MCP，有助调研且支持子 agent 时并行查（搜索文档、找类似 skill、查最佳实践），否则内联进行

## 第 2 步：裸跑（不写 skill 先跑 prompt）

`reference` 型（纯参考资料：只聚合信息、不改变行为决策）跳过本步

不写 skill，先跑 2–3 个典型 prompt，逐字记录：

- agent **怎么违反**：哪些该做的没做、哪些步骤漏了
- agent **说了什么借口**（"为简化" / "用户没说明" / "这样更快" / "应该等价"）——**原样**摘抄，不预写假想的借口

运行记录是起草的唯一输入。从记录判定失败类型再选形式：

- **纪律失败**（知道但找借口绕开）→ 禁令而非教程：把实录借口写进禁令句本身（"X 不构成…的理由"式）；禁令不加 "视情况" / "原则上" / "尽量" 类软开口；能机械拦截的进脚本，不靠文字约束
- **塑形失败**（想做但不会）→ 配方式步骤：具体步骤 + 例子 + 何时用
- **知识失败**（不知道 / 引用错地方）→ 参考资料式：聚合文档 + 链接 + 索引

## 第 3 步：起草 SKILL.md

frontmatter：按 `assets/skill-template.md` 的占位符填充；`description` 三组件格式与写法原则见[章节](description-workflow.md#description-优化原则)

正文：骨架从模板拷贝，**先填全再删节**（格式统一靠的是这份骨架，不是临场发挥）。节名 / 顺序 / 各类型可选性以模板为准；展开超一屏就下放 `ref/` 只留路标；所有参考文件从 `SKILL.md` 直接挂，`ref/a → ref/b` 的加载链（不读 b 就无法执行 a）禁止，"权威定义在 b"式指路可以。已知债：verify 会报 `BODY-SECTION-MISSING` WARN，属预期，不要为消 WARN 改回斜杠名

第 1 步标注的机械项此时落 `tools/` 清单，逐条过两问：

- 输出字节是输入的纯函数吗（不读正文内容、无权衡、无用户偏好）
- lint / 测试能验证产物吗（round-trip 可测）

两问都过 → 固化进脚本，正文只留"跑 X 命令"调用行；差一条 → 留 md 并记录理由。再算代价账：context 节省 × 频率是否高于脚本行数 + 豁免清单 + 配套冒烟的长期成本；一行 shell 能做完的、判定全靠人的、一年跑两次的，不值得脚本化

预检：`python -m tools.verify <skill-dir> --tier <default|reference|meta>`

## 第 4 步：测试用例

设计与裸跑同量级（2–3 条起步）的测试 prompt，用真实用户会说的话；**先给用户确认**（"这是我准备跑的几个测试用例，要不要再补几条"）再跑。存 `eval/evals.json`（结构见[章节](schemas.md#evalsjson)），此阶段只写 prompt，断言起草发生在评估循环里

## 第 5 步：评估循环与扩集

评估循环按[章节](improve-workflow.md#评估循环)执行（`--baseline without_skill`）；用户明确指示跳过时可不跑。收敛后测试集扩到 5–10 条（更广意图类别 + 相邻负例）再跑一轮防过拟合
