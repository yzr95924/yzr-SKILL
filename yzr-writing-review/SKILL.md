# yzr-writing-review

把文字 review 约束成**发现可追溯、结论可执行**的产物

## 输入与输出

| 方向 | 内容 |
| --- | --- |
| 输入 | 被审对象（文字 / 文档），可选附**参照输入**（SSOT 检查用）；多文件时互为参照输入，跨文档规则组随之启用 |
| 输出 | 对话式分析回答或报告形态，路由见[章节](#step-3-形态路由) |

## 执行原则

1. **不主动改文件**：产出是结论 / 报告，用户明确点头后才走改写（见[章节](#step-6-改写承接确认后)）
2. **每条发现可追溯**：映射到至少 1 个 catalog 规则名
3. **范围收敛**：只审 catalog 收录的场景；事实存疑只指出位置让用户人工核对、不展开验证
4. **产物留在对话内**：报告 / 结论不落成文件（落文件即成无人维护的第二真源）；多模型管线的
   中间产物（物化快照、扫描候选落盘）与自审机检物化的临时文件不受本条约束，落盘口径见[多模型编排](ref/multi-model.md)
5. **自审合规**：成文产物（报告形态输出 / Step 6 改写全文及其说明）交付前用 Step 2 的扫描脚本机检
   （对话内的先物化成临时文件），把归因于自己的命中清零；引用被审原文产生的命中免裁，其余豁免口径见
   [章节](ref/catalog.md#判定点)；自己行文再现同类命中等于结论失信

### 评审立场

评审立场单源在[章节](ref/catalog.md#评审立场)，默认路径与多模型评审员以该节为准

## 工作流

### Step 1: 收集输入

解析输入，确定语言 + 文体；判断有无**参照输入**。目录形式默认只含 `.md` 行文文件，
其余文件用户点名才进被审对象集

### Step 2: 加载 catalog 并补齐

必读 `ref/catalog.md`。可机械判定的候选先从 skill 根跑扫描：`python3 tools/scan_fingerprints.py
<被审对象>`；命中按对应规则处置，豁免按[章节](ref/catalog.md#判定点)（此口径与 reviewer.md 镜像，改动同步）。随后用
catalog 规则补齐发现；无参照输入时在结论里明确"本次只审文档内"。用户显式要求多模型 /
交叉评审时本步的发现生产整体改走[多模型编排](ref/multi-model.md)的 subagent 逐票，编排者不再自产发现

### Step 3: 形态路由

默认进 **对话式分析回答**（见[章节](#step-4-对话式分析回答默认)）；用户明确要报告时进
**报告形态**（见[章节](#step-5-报告形态)）；形态可中途切换

### Step 4: 对话式分析回答（默认）

1. **理解复述**：先用 2-4 句（句数与 reviewer.md 镜像，改动同步）讲清这段文字**在说什么**（核心主张）与**逻辑怎么走**（论证链条），
   拿不准处显式说"这里我理解为 X，若不对请纠正"
2. **结论先行**：一句话给出"有没有问题"（没有就说明理由，收尾）
3. **列要点**：按文档位置顺序（file:line / 章节先后），发现自带处置，不加严重度分级标签
   （Blocker / P0 类）；发现 ≤ 3 条直接给全（位置 + 规则名 + 问题 + 建议）；> 3 条给全量简表（每条一行）
4. **收尾问询**：发现多时问"逐条过一遍还是出一份报告"；逐条过按文档位置顺序逐条呈现，
   格式"**1/3** 位置 `规则名`：问题 + 建议。接受 / 改判 / 跳过 / 追问？"，每条等用户表态照词义处置，追问展开后进下一条
5. 逐条过完全部后输出汇总（接受 / 改判 / 跳过 计数 + 采纳清单），询问是否转报告形态
   或进入改写（见[章节](#step-6-改写承接确认后)）

### Step 5: 报告形态

按 `ref/report-template.md` 的节序输出（模板首节即理解复述）；末尾问用户下一步，推荐"逐条过"；"细化"适合发现少时，"改写"适合发现已逐条采纳后

### Step 6: 改写承接（确认后）

**对每条接受的发现，执行对应 catalog 规则的修法**；静默路径、执行约束、输出与自检见
[改写承接](ref/rewrite.md)
