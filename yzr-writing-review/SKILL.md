# yzr-writing-review

把文字 review 约束成**发现可追溯、结论可执行**的产物

## 输入与输出

| 方向 | 内容 |
| --- | --- |
| 输入 | 被审文字 / 文档，可选附**参照输入**（SSOT 检查用）；多文件目标文件集内部互为参照输入，跨文档规则组随之启用；单文件无参照输入时只审文档内 |
| 输出 | 对话式分析回答或报告形态，路由见[章节](#step-3-形态路由) |

## 执行原则

1. **不主动改文件**：产出是结论 / 报告，用户明确点头后才走改写（见[章节](#step-6-改写承接确认后)）
2. **每条发现可追溯**：映射到至少 1 个 catalog 规则名
3. **范围收敛**：只审 catalog 收录的场景；事实存疑只指出位置让用户人工核对、不展开验证
4. **产物留在对话内**：报告 / 结论不落成文件（落文件即成无人维护的第二真源）；多模型管线的
   中间产物（物化快照、扫描候选落盘）不受本条约束，落盘口径见[多模型编排](ref/multi-model.md)
5. **自审合规**：对话产物（回答 / 报告 / 交付说明）交付前先物化成临时文件，用 Step 2 的扫描脚本机检，
   把归因于自己的命中清零（豁免口径见 [章节](ref/catalog.md#判定点)）；自己行文出现被判罚的记号等于结论失信

### 评审立场

立场五条单源在[章节](ref/catalog.md#评审立场)，默认路径与多模型评审员以该节为准（Step 2 必读）

## 工作流

### Step 1: 收集输入

解析输入，确定语言 + 文体 + 篇幅；判断有无**参照输入**。目录目标默认只含工具枚举的行文文件，
其余文件用户点名才进目标集。篇幅以 `python3 tools/count_words.py
<目标>` 计（粘贴文字先物化成临时文件；从 skill 根运行），> 2000 字时与用户确认分段粒度
（按章节 / 按小节；多文件目标可按文件），发现按该粒度分批呈现

### Step 2: 加载 catalog 并补齐

必读 `ref/catalog.md`。可机械判定的候选先跑扫描：`python3 tools/scan_fingerprints.py
<目标文件 | 目录>`（从 skill 根运行；命中按对应规则处置，豁免按 [章节](ref/catalog.md#判定点)）。随后用
catalog 规则补齐发现；无参照输入时在结论里明确"本次只审文档内"。用户显式要求多模型 /
交叉评审时本步的发现生产整体改走[多模型编排](ref/multi-model.md)的子代理逐票，编排者不再自产发现

### Step 3: 形态路由

默认进 **对话式分析回答**（见[章节](#step-4-对话式分析回答默认)）；用户明确要报告时进
**报告形态**（见[章节](#step-5-报告形态)）；形态可中途切换

### Step 4: 对话式分析回答（默认）

1. **理解复述**：先用 2-4 句讲清这段文字**在说什么**（核心主张）与**逻辑怎么走**（论证链条），
   拿不准处显式说"这里我理解为 X，若不对请纠正"
2. **结论先行**：一句话给出"有没有问题"（没有就说明理由，收尾）
3. **列要点**：按文档位置顺序（file:line / 章节先后），发现自带处置，不加严重度分级标签
   （Blocker / P0 类）；发现 ≤ 3 条直接给全（位置 + 规则名 + 问题 + 建议）；> 3 条给全量简表（每条一行）
4. **收尾问询**：发现多时问"逐条过一遍还是出一份报告"；逐条过按文档位置顺序逐条呈现，
   格式"**1/3** 位置 `规则名`：问题 + 建议。接受 / 改判 / 跳过 / 追问？"，每条等用户表态照词义处置，追问展开后进下一条
5. 逐条过完全部后输出汇总（接受 / 改判 / 跳过 计数 + 采纳清单），询问是否转报告形态
   或进入改写（见[章节](#step-6-改写承接确认后)）

### Step 5: 报告形态

开头先做**理解复述**（口径同[章节](#step-4-对话式分析回答默认)的第 1 步，不超过一段），
再按 `ref/report-template.md` 输出；末尾问用户下一步（细化 / 逐条过 / 改写）

### Step 6: 改写承接（确认后）

**对每条接受的发现，执行对应 catalog 规则的修法**。用户显式说"直接改，不用审"时跳过 review，
静默对照 `ref/catalog.md` 定位问题（不出结论）再按修法改；说明以一句对原文的精简理解开头

执行约束：

- **长度目标**（"压到 N 字 / 砍到 X%"）：存疑保留项可为达标让路（"永不可砍"不受影响）；
  达不到时一行如实报告最小可达字数与原因（不占说明额度）
- **永不可砍**：事实 / 数据 / 结论 / 引用一克不少（拿不准的标"存疑请人工核对"）；
  caveats（"但 / 然而 / 前提是"引出的限定条件）；用户点名保留的内容；Markdown 结构
  （标题层级 / frontmatter / 代码块 / 链接 / 图片引用 / 表格 / 列表嵌套）原样不动
- **就地编辑保护**：文件被 git 跟踪就直接就地编辑，说明里提示"`git diff` 可核对 / 恢复"；
  不在版本控制下时，删掉的**整段原文**必须附在输出末尾"已删内容"块（不占说明额度），
  否则不许就地删，先贴原文再问用户

**输出**：

1. 改写后的完整版本（文件输入就地编辑，粘贴输入在对话内输出全文）
2. 压缩率一行：`X 字压到 Y 字（-Z%）`，X / Y 取 `tools/count_words.py` 数字（中文按字符数
   不含空白、英文按词数）；只做风格 / 语气改动、字数未降时写"字数基本持平"
3. 最多 3 行说明：每条改动引用 ≥ 1 个 catalog 规则名；存疑待核一条一行。说明比改写版
   还长时删说明

**自检**：交付前用 catalog 相关规则回扫改写产物，**零新发现才交付**；有新发现就修掉或回滚该处
