# 多模型评审编排

多模型只替换 Step 2 的发现生产，Step 3-6 机制不变，呈现层的分组与来源标注由[章节](#合并)增补；
[评审员契约](reviewer.md)的复述句数口径与 [章节](../SKILL.md#step-4-对话式分析回答默认) 互为镜像
（评审员材料清单不含 SKILL.md，只能复制），改一侧须同步另一侧

**存在理由**：多评审员读同一份卷宗出发现，共识与分歧都能显式化

**机制铁律**：评审员票一律由 harness 的 subagent 产生，不起 `opencode run` 之类 CLI 子进程
（那等于在脚本里重造 harness 原生的并行与送达，还要随每次 CLI 版本漂移修脚本）。
用户显式要求多模型评审即构成逐票指定 model 的显式授权

## 编排

1. 物化：被审对象若是粘贴文字，先写成快照文件（系统临时目录下）；磁盘文件用原路径
2. 扫描候选落盘：从 skill 根跑 `python3 tools/scan_fingerprints.py <被审对象> --json`，输出存成文件
   （粘贴文字与快照同目录；磁盘被审对象落系统临时目录的会话专属目录）；机械扫描由编排者跑一次，各评审员读同一份落盘结果、不自行重跑
3. spawn：名单每个模型一票，用 harness 的 subagent 工具**一条消息并行发起全部票**。逐票 prompt
   全同：角色句（"你是 N 名独立评审员之一。只读下方材料清单列出的文件，按评审员契约规定的角色、
   评审立场与产物顺序，在回复正文直接产出最终评审，最终回复即交付物"）+ 对象说明（被审对象与启用的条件规则组；规则清单同时被审时声明元提及豁免；不转述主对话里的用户评价与怀疑点，避免锚定各票）
   + 绝对路径清单（被审对象全文、参照输入如有、扫描候选文件、
   [评审员契约](reviewer.md)、[规则清单](catalog.md)）。票间唯一差异是模型参数，取名单表的精确 ID
4. **编排者不评审**：编排者上下文含主对话、与评审员不对称，亲自评审会击穿同一性保证；不对称在上下文
   不在模型名，会话模型在名单内时照常入票
5. 回退：harness 无可指定 model 的 subagent、或评审员读盘不可用时如实告知，退回单模型现状；部分票
   失败的用余下有效票照常合并、以名单为分母逐票披露状态，全部票失败同样退回单模型现状，不凭记忆补发现
6. 每票审全文、不分段：跨段问题（前后重复、结构缺陷）是全文评审的固有意义

## 合并

对每票输出先按[评审员契约](reviewer.md)的产物节核对（复述段、发现行、引用文件在清单内且行号对得上现文）再处置；
不合契约的票（如无发现行）不强行解析成发现，如实披露该票状态（重跑口径见第 1 条）：

1. 对比理解复述：核心主张明显跑偏的票降权（其发现不计共识、保留时标注来源于降权票），结论写明原因；重跑只征询用户，不擅自
2. 同位置、同规则名且语义指向同一问题的发现归并为一条，记来源模型集合；位置相邻但处置对象不同的不并，宁可留两条；
   跨文档发现统一锚非权威源侧，对方坐标写进问题字段；引用评审员原文作证据时逐字，不翻译、不转写
3. 分级呈现：共识（≥2 模型）独立成组排前，其后列单模型发现并标"仅 X 提出"，组内按文档位置排序；
   不可核验的全文计数不构成降出共识的理由，存疑即标注交用户；映射不到 catalog 规则名的发现由编排者尝试映射，映射不上按范围收敛过滤，不进合并清单
4. 冲突（同一位置给出互斥处置，如一方判删、另一方判补或保留）单列"分歧"：对话式排在单票组后
   独立成组，报告形态入主表（列首措辞以[报告模板](report-template.md)为准），不静默裁决；编排者给资深架构师倾向，最终交用户表态
5. 来源标注落在现有输出格式内（报告形态列口径见[报告模板](report-template.md)）：对话式在规则名后附
   `【A+B】` / `【仅 X】`
6. 有效票仅 1 时如实声明"多模型实际退化为单票"，该票清单直接进 Step 3，不分组、不标来源
7. 各票的"不报告项"不合并不标来源；呈现按 catalog"洁癖但克制"口径
8. 合并后的清单进 Step 3-6
