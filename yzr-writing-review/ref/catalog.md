# 文档审查规则清单（SSOT）

同一处文字命中多条规则：按最贴根因的一条报，连带症状写进建议，不拆成两条
子项标签：不报 列豁免，注意 列护栏；条件节启用条件写在标题括号

## 通用规则

- **论证缺陷**：主张与证据、或前后对不上
  - 矛盾：请作者裁定，不替选
  - 缺口 / 指代落空：补桥接句与前提
  - 结论与论据脱节：收窄结论或补论据
  - 无依据 / 推测：降级为"我们认为"或删；援引调研：补对象与规模
- **详略与范围**：范围漂移改标题、正主以用户意图为准；主次颠倒重分配篇幅；离题 / 多余内容删或移附录；
  句内过度举例留 2–3 个
  - 不报：清单本身是交付物时不动列举
- **信息组织**：章节交叉的合并或明确分工；先结论后定义这类放置错位移位；
  三级以下标题每节只剩一句话的并回段落
- **易漂移引用**：行号 / commit / 章节号等会失效的坐标；代码侧改稳定符号名 + 路径、章节改标题锚点；
  确需坐标注明快照口径
  - 不报：纯散文不适用
- **冗余重复**：删掉后信息量不损失，一律删或换直说
  - 词级：近义词并列 / "的"链 / 冗长功能词 / 程度副词与限定词；连接词接力一段 ≤ 1；双重强调拆成两句
  - 句级：填充句
  - 段级：同义重述（图 / 表 / 散文 / 列表跨体裁各写一遍），留信息量大的那版
  - 篇级：注水开头结尾；摘要与预告互注（不足 1500 字删两者，长文档摘要只留"为什么 + 结论"）；序号词全文 ≤ 3 个
  - 不报：程度副词 / 限定词承载实测对比时保留
- **句式与段落**：中文单句 > 60 字 / 英文 > 35 词无必要嵌套就拆；连续 5 句以上等长砍一句成短句；
  同段用连接词另起新论点拆段；并列项结构混排对齐；连续被动改主动；括号只装插入语，阈值与例外写进主句
  - 不报：执行者未知 / 刻意弱化的被动
- **具体与动词化**：抽象表达替代可验证事实（如抽象名词 + 空动词），换具体数据；"进行 / 实施 / 做出 + 名词"、
  make / perform + noun 直接用动词；黑话堆砌与英文万能动词换常用说法、plays a role 类写出具体作用
  - 不报：术语性抽象名词与技术专有语境保留
  - 注意：没数据不许编造，改泛指但具体
- **一致**：概念选定一词全文统一，专名首次中英对照后固定一种；人称统一（中文技术文档用"你"、
  英文指南用 you、决策记录用 we）；不为避免重复换同义词
- **语气与分寸**：先判文体再收敛正式度（技术文档冷静 / wiki 半正式 / 邮件礼貌直接 / 公告克制）；
  多重对冲一句 ≤ 1 个、一段 ≤ 2 个；指令用祈使句、主张用陈述句 + 依据，中文按惯例改用陈述句；敬语能省则省
  - 不报：有依据的不确定保留并写明依据；对上级与对外保留协商式
- **讨好与推销腔**：文字在服务作者形象或推销而非给读者信息；开场捧场 / 过度感谢道歉 / 自我贬抑铺垫删；
  营销词、宏大叙事与感叹号连用换可验证说法；感叹号全文 ≤ 1
  - 不报：邮件真实社交语境保留寒暄
  - 注意：事实性强宣称无依据按 论证缺陷 判

## AI 腔指纹

AI 生成文本的高频"指纹"：只管识别，命中按对应规则处理

### 结构指纹（中英通用）

- **三段式总结**：正文已经说清楚，结尾再来"综上所述 / In summary"复述。按 冗余重复 篇级删
- **加粗成瘾**：每段都有加粗短语，或连续段落都以"**重点**：" / "**Key point:**"式小标题开头。
  只保留真正需要扫读定位的，如术语定义与警告，其余去粗体
- **排比成瘾**：连续三句以上同构排比（"它是……，它是……，它是……"）。保留一组，
  其余改正常句式
- **列表瘾**：一句话能说清的也拆成 bullet。合并回句子；真清单保留
- **总分总强迫**：无论什么内容都"总起—分述—总结"。短篇删总起和总结
- **假装对话**：非对话文体里插入"你可能会问……"自问自答。改陈述；FAQ 文体保留

### 标点与排版指纹

- **破折号"——"/ em-dash**：一律换常规标点，插入语改括号或逗号、并列补述改冒号或另起句号；
  真正的修辞停顿保留
- **CJK 角引号"「」/『』"**：中文技术文档正文用弯双引号""，混入「」『』属风格漂移，改""；
  其他语言原文语境保留
- **§ 章节符号**：行文里用 § 指章节。改"3 节 / 第 3 章"式写法；法学 / 标准条文引用等专有语境
  保留，坐标漂移另按 易漂移引用 判
- **→ 箭头**：行文里用 → 表推导 / 因果。拆成正常句子，如"引入缓存后延迟下降"；
  步骤链 / 映射表等记号语境按 判定点 判
- **emoji 点缀**：技术文档 / 正式文档里的装饰性 emoji。删；用户原文自带且文体允许如个人笔记保留
- **"首先 / 其次 / 最后"序号词**：与编号列表同时出现时删序号词，密度超限按 冗余重复 判

### 判定点

- 单处指纹出现 ≠ AI 生成，人也会写"值得注意的是"；**跨类命中 ≥ 3 处**才整体按"去 AI 腔"
  处理，单处命中按对应规则处理
- 指纹清单是删改依据，不是禁用词表：引文、反讽与专有名词等语境需要时保留
- 处理目标不是"检测不出来"，是"读着像作者自己写的"。别为了规避检测引入怪句

## 跨文档 SSOT（仅参照输入存在时启用）

SSOT 是贯穿原则：单文档内重复归 冗余重复、说法不统一归 一致、前后不一归 论证缺陷、分散多节
归 信息组织；本节四条都是通用规则的跨文档版、只写差异。权威源 = 用户指定的正本，未指定按
仓库约定位置判，定不了请作者裁定、不自行选边

- **口径漂移**：一致 的跨文档版，含两处定义互相矛盾。统一到权威源，另一处改引用
- **内容重复**：冗余重复 段级的跨文档版，逐字或逐段重复。删重复段，改为指向权威源的引用
- **跨文档重述定义**：冗余重复 段级同义重述的跨文档版。压成一句引用 + 链接，不重写定义
- **事实冲突**：论证缺陷 矛盾型的跨文档版。按那条处置，并给出双方文件与位置

## 指令文档（被审对象是 agent 指令时启用）

适用对象：SKILL.md / AGENTS.md / CLAUDE.md / system prompt / rules 文件 / CLI 工具说明。判据是
agent 读者版：冗余从"读者有损失吗"变成"**删掉这句，称职 agent 会做错吗？不会就删**"；判据要查
文本外证据时只报现象、标存疑，不下"该删"判决

- **agent 通识复述**：把 agent 本就会的操作逐步铺开、写成整段散文或复述已知通识；前者删或换成
  一行命令，后者删或压成一句
  - 不报：agent 不可能知道的（私有格式 / 环境怪癖 / 踩过的坑）
- **疤痕组织**：为单次历史失败打的补丁句，如"别忘了 X"式防御句，或预先回应假想误读；标存疑
  请作者溯源，确无来源的删，确有护栏必要的改写成"该做什么"的正面规则一句
- **禁令无 why**：NEVER / ALWAYS 类禁令没给理由句，成片堆叠的更严重；补"为什么"，补不出理由
  的标存疑交作者裁定
- **时间性信息内联**："自 v2 起删除了 X"等演进史写进规范正文，agent 会把旧行为当成可选路径；
  演进叙事归 git，正文最多留一句路标
  - 不报：外部依赖版本约束（如"Python ≥ 3.7"）
- **决策点多等价选项**：≥ 3 个等价选项不给推荐，agent 只能随机挑一个或反问用户；给 1 个推荐 +
  1 个逃生舱兜底，其余选项各用一句写清何时才选它
- **示例堆叠**：同一要点配多个块级示例，如模板填空 × N、多语言各写一遍；留一个最相关的完整示例
