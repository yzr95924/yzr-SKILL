# 文档审查规则清单（SSOT）

本文件是 yzr-writing-review skill 的核心知识资产：规则清单（含 AI 腔指纹表与两个条件节），
细则自含，无第二层规则文件。每条发现必须映射到至少 1 条规则。

## 怎么读

每条规则一行：**名称** + 现象一句 + 修法一句；括号内为例外 / 判别，是判定标准的一部分。
引用一律用规则名。AI 腔一节是指纹表形态（表格 + 判定点）：指纹管识别，命中后按表内指向的
规则处理。

---

## 通用规则

- **逻辑矛盾**：同一文档两处说法直接打架（结论对结论 / 数据与结论相反 / 定义前后不一）。
  指出两处 + 摘录原文，请作者裁定，不替选
- **论证链断裂**：推理跳环节（"因为并发高，所以要用 Kafka"缺"队列已到上限"）/ 隐藏前提未声明 /
  "如上所述"指到不存在的内容。补桥接句、前提显式化
- **结论与论据脱节**：以偏概全 / 反例未处理 / 证据错位。收窄结论到论据能支撑的范围或补论据，
  都不行就删
- **无依据断言**："最 / 第一 / 业界领先"无数据、"根据调研"无对象与规模、推测写成陈述。
  降级为"我们认为" + 补依据，给不出就删；存疑标"请人工核对"
- **范围漂移**：标题 / 开头承诺的范围与正文不符、附录级细节混入主干。对齐：改标题 / 删多余 /
  移附录（哪边是正主以用户意图为准）
- **主次颠倒**：决定成败的论证一句话带过、无关背景展开最长。关键点展开到读者能带走结论，
  细节压缩 / 移附录，只改分配不改事实
- **离题段**：整段与主题无关（背景跑偏 / 历史沿革 / 方法论自夸）。删段或移附录
  （范围承诺不符按 范围漂移 判）
- **同义重述**：同一观点换说法再讲一遍（句级"换句话说"类 / 段级整段复述），没有新信息。
  保留信息量大的那版
- **章节职责交叉**：两章讲同一件事 / 同一信息分散多节。合并或明确"A 节讲定义、B 节讲用法"的分工
- **信息放置错位**：前置条件放后面讲 / 先结论后定义。移到正确位置，保证线性阅读顺序
- **层级碎片化**：三级以下标题每节只有一句话 / 列表套列表。合并层级，内容收拢回段落
- **填充句**：删掉后段落意思不变的句子（"这是一个非常重要的话题。"类）。删
- **过度限定词**：非常 / 极其 / 相当 / really / very / quite 类。默认删（限定词承载实测对比时保留）
- **注水开头结尾**：开头"在当今……时代 / 随着……的发展"、结尾"总而言之"+复述。从正题起笔；
  结尾有行动项改一句行动号召
- **同义堆叠**：近义词并列当盾（"帮助和协助" / "each and every"）。留一个最准的
- **中文"的"链与"是……的"**："的"连用 ≥ 3 次 / 非必要"是……的"强调。拆链直说
  （"系统的配置的管理的界面"改成"系统配置管理界面"）；空动词按 去名词化 判
- **英文功能词冗余**：in order to / due to the fact that / at this point in time / "There is-are"开头。
  换成 to / because / now / 直接主语起句
- **过度举例**："例如 A、B、C、D、E、F"列一长串。留 2–3 个最有代表性的（清单本身是交付物时不动）
- **摘要与正文互注水**：摘要逐节复述 + 正文"本节将介绍"预告。短文档（< 1500 字）删摘要 / 预告；
  长文档摘要只留"为什么 + 结论"
- **句式长短错落**：连续 5 句以上长度相近。砍一句成短句，制造停顿
- **拆超长句**：中文单句 > 60 字、英文 > 35 词且无必要逻辑嵌套。拆
- **一段一意**："另一方面 / additionally / 同时"开启新论点。拆段，一段一个论点
- **主动语态优先**：连续被动 / 无主语被动让执行者消失。改主动（执行者未知 / 不重要 /
  刻意弱化时保留）
- **具体优先于抽象**：抽象名词 + 空动词替代可验证事实（"有一定的提升空间"）。换具体数据；
  原文没数据**不许编造**，改泛指但具体的说法
- **去名词化**："进行 / 实施 / 做出 + 名词"、"make / perform + noun"。直接用动词
- **术语一致性**：同一概念全文多个词。选定一词全文统一；专名首次出现给中英对照后固定一种；
  不为"避免重复"换同义词（换词 = 换概念）
- **连接词节制**："因此 / 然而 / 此外 / 所以"每段开头都出现。能靠语序表达的就删，一段最多留一个
- **并列结构对齐**：并列项语法结构不一致（名词 / 动宾 / 完整句混排）。对齐
- **易漂移引用**：用行号 / commit 哈希 / "见 §3.2" 等会失效的坐标做引用。代码侧改稳定符号名 +
  路径、章节引用改标题锚点；确需坐标注明快照口径（纯散文不适用）
- **正式度匹配文体**：正式度与文体不符（技术文档里网络用语 / 感叹号连用 / emoji）。先判文体
  再收敛：技术文档冷静陈述、wiki 半正式、邮件礼貌直接、公告正式克制
- **去谄媚**：捧场开头（"好问题！"）/ 过度感谢道歉 / 自我贬抑铺垫。删，直接给内容
  （邮件真实社交语境保留）
- **去营销腔**：技术内容里的广告词（极致性能 / 完美解决 / seamlessly）。换可验证说法；
  感叹号全文 ≤ 1 个（事实性强宣称无依据按 无依据断言 判）
- **人称一致**："你 / 您 / 我们"随机轮换。全文统一：中文技术文档默认"你"，英文指南统一
  "you"、决策记录统一 "we"
- **中英语气差异**：按字面对译另一语言的语气。用目标语言惯例：英文祈使句开头（"Run the tests"）、
  中文陈述句（"先跑测试"）；中文"请"能省则省
- **对冲节制**：hedging 连用（"可能在某种程度上或许"）。一句 ≤ 1 个、一段 ≤ 2 个；有依据的
  不确定保留对冲并写明依据
- **命令式与建议式的分寸**：指令犹豫（"你可能想要考虑运行 X"）/ 主张含糊。指令用祈使句、
  主张用陈述句 + 依据；对上级 / 对外保留协商式

## AI 腔指纹表

AI 生成文本的高频"指纹"。命中即按对应处理改写或删除。

### 中文指纹

| 指纹 | 处理 |
| --- | --- |
| "在当今快节奏的 / 瞬息万变的……时代 / 领域" 开头 | 见 注水开头结尾 |
| "随着……的不断发展 / 日益普及" | 见 注水开头结尾 |
| "值得注意的是 / 需要指出的是 / 众所周知" | 见 填充句 |
| "不言而喻 / 毋庸置疑 / 显而易见" | 见 填充句 |
| "让我们（一起）深入探讨 / 一探究竟" | 见 注水开头结尾 |
| "不仅……而且……" 双重强调 | 拆成两句，或删"不仅而且" |
| "赋能 / 抓手 / 闭环 / 链路 / 颗粒度" 等黑话堆砌 | 换成具体说法；技术专有语境保留 |
| "总的来说 / 总而言之 / 综上所述" + 全文复述 | 见 注水开头结尾 |
| "作为……，它……" 万能开头（"作为一个 AI 助手"） | 见 注水开头结尾 |
| "的浪潮 / 的变革 / 的新篇章" 宏大叙事 | 换成具体事实 |
| "首先……其次……再次……最后……" 五段俱全 | 保留 ≤ 3 个，其余靠语序 |

### 英文指纹

| 指纹 | 处理 |
| --- | --- |
| "In today's fast-paced world" | 见 注水开头结尾 |
| "It's worth noting that / It is important to note that" | 见 填充句 |
| "delve into / embark on / navigate the landscape of" | 换成 dig into / start / handle 或直接动词 |
| "leverage / utilize" 滥用 | 换成 use（专有技术语境如 leverage a cache 保留） |
| "furthermore / moreover / additionally" 每段开头接力 | 见 连接词节制 |
| "not only … but also …" 每篇必现 | 拆句或删 |
| "In conclusion / To summarize" + 全文复述 | 见 注水开头结尾 |
| "plays a (crucial/vital/pivotal) role in" | 换成具体作用："X handles Y" |
| "a testament to" / "a game-changer" / "the power of" | 删或换事实 |
| "Great question! / Certainly! / Absolutely!" 对话捧场 | 见 去谄媚 |
| "seamlessly / effortlessly / robust" 副词三连 | 见 去营销腔 |
| 过度 hedging："It's worth mentioning that it might potentially…" | 见 对冲节制 |

### 结构指纹（中英通用）

- **三段式总结**：正文已经说清楚，结尾再来"综上所述 / In summary"复述。删
- **每段加粗小标题**：连续段落都以"**重点**：" / "**Key point:**"开头。保留真需要的，
  其余去粗体
- **排比成瘾**：连续三句以上同构排比（"它是……，它是……，它是……"）。保留一组，
  其余改正常句式
- **列表瘾**：一句话能说清的也拆成 bullet。合并回句子；真清单保留
- **总分总强迫**：无论什么内容都"总起—分述—总结"。短篇删总起和总结
- **假装对话**：非对话文体里插入"你可能会问……"自问自答。改陈述；FAQ 文体保留

### 标点与排版指纹

- **破折号"——"/ em-dash**：默认一律换常规标点（插入语改括号或逗号，并列补述改冒号
  或另起句号）；豁免收窄到引文与真正的修辞停顿。中文 AI 腔最高频指纹之一，单点命中
  即处理、不等密度阈值
- **CJK 角引号"「」/『』"**：中文技术文档正文用弯双引号""，混入「」属风格漂移，『』同理。
  单点命中，改""（引文与其他语言原文语境豁免）
- **§ 章节符号**：行文里用 § 指章节（"详见 §3.2"）是 LLM 高频记号。改"3 节 / 第 3 章"式写法
  （法学 / 标准条文引用等专有语境保留；坐标漂移另按 易漂移引用 判）
- **→ 箭头**：行文里用 → 表推导 / 因果（"引入缓存 → 延迟下降"）是 LLM 高频记号。拆成正常
  句子（"引入缓存后延迟下降"）；步骤链 / 映射表等记号语境按 判定点 判
- **emoji 点缀**：技术文档 / 正式文档里段落开头 emoji（🚀💡✨）。删；用户原文自带且
  文体允许（个人笔记）保留
- **加粗成瘾**：每段都有加粗短语。只保留真正需要扫读定位的（术语定义 / 警告）
- **"首先 / 其次 / 最后"序号词** 与编号列表同时出现。删序号词

### 判定点

- 单个指纹出现 ≠ AI 生成，人也会写"值得注意的是"；**命中 ≥ 3 类指纹**才按"去 AI 腔"
  处理，单点命中按对应规则处理
- 黑名单是删改依据，不是禁用词表：语境需要时（引文 / 反讽 / 专有名词）保留
- 处理目标不是"检测不出来"，是"读着像作者自己写的"。别为了规避检测引入怪句

## 跨文档 SSOT（仅参照输入存在时启用）

- **口径漂移**：同一概念两处定义 / 术语用法不一致。统一到参照输入的 SSOT 版本，另一处改引用
- **内容重复**：本文与参照文档逐字 / 逐段重复。删重复段，改为指向 SSOT 的引用
- **事实冲突**：数据 / 结论与参照文档矛盾。指出冲突双方位置，请作者裁定谁为准，改另一处
- **上下文重复定义**：已在 SSOT 定义过的概念又展开重述。一句话引用 + 链接，不重写定义

## 指令文档（被审对象是 agent 指令时启用）

适用对象：SKILL.md / AGENTS.md / system prompt / rules 文件 / CLI 工具说明。读者是执行中
的 agent 而非人。判据是 agent 读者版：冗余从"读者有损失吗"变成"**删掉这句，称职 agent
会做错吗？不会就删**"。

- **agent 通识复述**：把 agent 本就会的操作逐步铺开 / 复述通识概念 / 一行命令能替代的写成
  整段散文。删或替换为一行命令；只保留 agent 不可能知道的（私有格式、环境怪癖、踩过的坑）；
  成片出现按 同义重述 判
- **疤痕组织**：为单次历史失败打补丁（"别忘了 X"式防御句）/ 预先回应假想误读。删（没来自
  实际失败的补丁 = 无依据）；确有护栏必要改写成正面规则一句
- **禁令无 why**：NEVER / ALWAYS 堆叠且无理由句。补"为什么"（agent 依理由而非词强遵从）；
  补不出理由的禁令大概率本就该删（常与 疤痕组织 同现）
- **时间性信息内联**："自 v2 起删除了 X"等演进史写进规范正文（agent 会把旧行为当成可选路径）。
  演进叙事移 git commit / CHANGELOG，正文最多留一句路标（外部依赖版本约束如"Python ≥ 3.7"照写）
- **决策点 N 等价选项**：≥ 3 个等价选项不给推荐。1 个推荐 + 1 个 escape hatch，其余收进
  "何时才选它"一句限定
- **示例堆叠**：同一要点配多个平庸样例（模板填空 × N、多语言各写一遍）。留一个最相关的完整
  示例（与 过度举例 分工：它管内联列举，本条管块级示例）

### 本节三条判定注

- **同 skill 内重抄**：同一规则在 SKILL.md 与 ref/ 多处展开。按 内容重复 判，删重处留指针
  （对 skill 文件集做体检时，该文件集自身就是参照输入）
- **跨体裁双写**：同一信息以图 / 表 / 散文 / 列表各承载一遍。按 同义重述 判，语义归并只留一份
- **description 常驻（SKILL 类文档特轴）**：frontmatter description 等价于一直加载，正文复述其
  触发语 / 路由结论。按 内容重复 同文档双写判、删正文侧；审 SKILL.md 必须把 frontmatter 纳入
  比对视野（权限 / 纪律句在执行点的重述豁免，归通用删除测试判）
