# 文档审查规则清单（SSOT）

本文件是 yzr-writing-review skill 的核心知识资产：规则清单（含 AI 腔指纹表与两个条件节），
细则自含，无第二层规则文件。每条发现必须映射到至少 1 条规则。

## 怎么读

每条规则两句：第一句判定点（这条管什么，一眼定位），第二句修法（每个子类一个关键词、阈值
内联；类别名不足以触发识别时才加 3–6 字注脚）。引用一律用规则名。AI 腔一节是指纹表（表格 +
判定点）：指纹管识别，命中后按表内"处理"列的规则处理，规则层不重复计同一说法。

---

## 通用规则

- **论证缺陷**：主张与证据、或自身前后对不上。修法：矛盾指出两处请作者裁定不替选、缺口与
  指代落空补桥接句与前提、脱节收窄结论或补论据、无依据与推测写成陈述降级为"我们认为"或删
- **详略与范围**：篇幅分配与承诺范围失当。修法：范围漂移改标题、删多余或移附录，正主以用户
  意图为准；主次颠倒重分配篇幅；离题段删或移附录；过度举例留 2–3 个，但清单本身是交付物时
  不动列举
- **信息组织**：同一信息的位置与层级不对。修法：章节交叉的合并或明确各节分工，谁讲定义谁讲
  用法讲清；先结论后定义这类放置错位移位，保证线性阅读；三级以下标题每节只剩一句话的层级
  碎片化并回段落；跨文档重复按 跨文档 SSOT 判
- **易漂移引用**：用行号 / commit 哈希 / 章节号等会失效的坐标做引用。修法：代码侧改稳定符号名 +
  路径、章节改标题锚点，确需坐标注明快照口径；纯散文不适用
- **冗余重复**：删掉后信息量不损失，四粒度：词级的近义词并列、中文"的"链、程度副词与限定词、
  冗长功能词、连接词接力；句级的填充句；段级的同义重述，含图 / 表 / 散文 / 列表跨体裁各写
  一遍；篇级的注水开头结尾、摘要与预告互注。修法：一律删或换直说，段级留信息量大的那版，
  连接词一段 ≤ 1，不足 1500 字的短文档删摘要与预告，长文档摘要只留"为什么 + 结论"
- **句式与段落**：句子与段落的形状妨碍阅读。修法：中文单句 > 60 字 / 英文 > 35 词且无必要嵌套
  就拆、连续 5 句以上等长砍一句成短句、同段用连接词另起新论点拆段、并列项结构混排对齐、
  连续被动改主动但执行者未知或刻意弱化时保留、括号只装插入语而阈值与例外写进主句
- **具体与动词化**：抽象表达替代可验证事实。修法：抽象名词 + 空动词换具体数据，没数据**不许
  编造**、改泛指但具体的说法；"进行 / 实施 / 做出 + 名词"与 make / perform + noun 这类名词化
  直接用动词；术语性抽象名词保留
- **一致**：同一事物全文用了多个说法。修法：概念选定一词全文统一，专名首次给中英对照后固定
  一种；人称统一，中文技术文档用"你"、英文指南用 you、决策记录用 we；不为避免重复换同义词，
  换词就是换概念
- **语气与分寸**：语气强弱或正式度与文体、读者不匹配。修法：先判文体再收敛正式度，技术文档
  冷静、wiki 半正式、邮件礼貌直接、公告克制；多重对冲收敛到一句 ≤ 1 个一段 ≤ 2 个，但有依据
  的不确定保留并写明依据；指令用祈使句而主张用陈述句 + 依据，对上级与对外保留协商式；按目标
  语言惯例走，英文用祈使句、中文用陈述句，敬语能省则省
- **讨好与推销腔**：文字在服务作者形象或推销，不在给读者信息。修法：开场捧场 / 过度感谢道歉 /
  自我贬抑铺垫删，但邮件真实社交语境保留寒暄；营销词与感叹号连用换可验证说法、感叹号全文
  ≤ 1；事实性强宣称无依据按 论证缺陷 判

## AI 腔指纹表

AI 生成文本的高频"指纹"。命中即按对应处理改写或删除。

### 中文指纹

| 指纹 | 处理 |
| --- | --- |
| "在当今快节奏的 / 瞬息万变的……时代 / 领域" 开头 | 见 冗余重复 |
| "随着……的不断发展 / 日益普及" | 见 冗余重复 |
| "值得注意的是 / 需要指出的是 / 众所周知" | 见 冗余重复 |
| "不言而喻 / 毋庸置疑 / 显而易见" | 见 冗余重复 |
| "让我们（一起）深入探讨 / 一探究竟" | 见 冗余重复 |
| "不仅……而且……" 双重强调 | 拆成两句，或删"不仅而且" |
| "赋能 / 抓手 / 闭环 / 链路 / 颗粒度" 等黑话堆砌 | 换成具体说法；技术专有语境保留 |
| "极致性能 / 完美解决 / 一键解决" 等营销词 | 见 讨好与推销腔 |
| "总的来说 / 总而言之 / 综上所述" + 全文复述 | 见 冗余重复 |
| "作为……，它……" 万能开头（"作为一个 AI 助手"） | 见 冗余重复 |
| "的浪潮 / 的变革 / 的新篇章" 宏大叙事 | 换成具体事实 |
| "首先……其次……再次……最后……" 五段俱全 | 保留 ≤ 3 个，其余靠语序 |

### 英文指纹

| 指纹 | 处理 |
| --- | --- |
| "In today's fast-paced world" | 见 冗余重复 |
| "It's worth noting that / It is important to note that" | 见 冗余重复 |
| "delve into / embark on / navigate the landscape of" | 换成 dig into / start / handle 或直接动词 |
| "leverage / utilize" 滥用 | 换成 use（专有技术语境如 leverage a cache 保留） |
| "furthermore / moreover / additionally" 每段开头接力 | 见 冗余重复 |
| "not only … but also …" 每篇必现 | 拆句或删 |
| "In conclusion / To summarize" + 全文复述 | 见 冗余重复 |
| "plays a (crucial/vital/pivotal) role in" | 换成具体作用："X handles Y" |
| "a testament to" / "a game-changer" / "the power of" | 删或换事实 |
| "Great question! / Certainly! / Absolutely!" 对话捧场 | 见 讨好与推销腔 |
| "seamlessly / effortlessly / robust" 副词三连 | 见 讨好与推销腔 |
| 过度 hedging："It's worth mentioning that it might potentially…" | 见 语气与分寸 |

### 结构指纹（中英通用）

- **三段式总结**：正文已经说清楚，结尾再来"综上所述 / In summary"复述。删
- **每段加粗小标题**：连续段落都以"**重点**：" / "**Key point:**"开头。保留真需要的，
  其余去粗体
- **排比成瘾**：连续三句以上同构排比（"它是……，它是……，它是……"）。保留一组，
  其余改正常句式
- **列表瘾**：一句话能说清的也拆成 bullet。合并回句子；真清单保留
- **总分总强迫**：无论什么内容都"总起—分述—总结"。短篇删总起和总结
- **假装对话**：非对话文体里插入"你可能会问……"自问自答。改陈述；FAQ 文体保留

### 标点与排版指纹

- **破折号"——"/ em-dash**：默认一律换常规标点（插入语改括号或逗号，并列补述改冒号
  或另起句号）；豁免收窄到引文与真正的修辞停顿。中文 AI 腔最高频指纹之一，单点命中
  即处理、不等密度阈值
- **CJK 角引号"「」/『』"**：中文技术文档正文用弯双引号""，混入「」属风格漂移，『』同理。
  单点命中，改""（引文与其他语言原文语境豁免）
- **§ 章节符号**：行文里用 § 指章节（"详见 §3.2"）是 LLM 高频记号。改"3 节 / 第 3 章"式写法
  （法学 / 标准条文引用等专有语境保留；坐标漂移另按 易漂移引用 判）
- **→ 箭头**：行文里用 → 表推导 / 因果（"引入缓存 → 延迟下降"）是 LLM 高频记号。拆成正常
  句子（"引入缓存后延迟下降"）；步骤链 / 映射表等记号语境按 判定点 判
- **emoji 点缀**：技术文档 / 正式文档里段落开头 emoji（🚀💡✨）。删；用户原文自带且
  文体允许（个人笔记）保留
- **加粗成瘾**：每段都有加粗短语。只保留真正需要扫读定位的（术语定义 / 警告）
- **"首先 / 其次 / 最后"序号词** 与编号列表同时出现。删序号词

### 判定点

- 单个指纹出现 ≠ AI 生成，人也会写"值得注意的是"；**命中 ≥ 3 类指纹**才按"去 AI 腔"
  处理，单点命中按对应规则处理
- 黑名单是删改依据，不是禁用词表：语境需要时（引文 / 反讽 / 专有名词）保留
- 处理目标不是"检测不出来"，是"读着像作者自己写的"。别为了规避检测引入怪句

## 跨文档 SSOT（仅参照输入存在时启用；审多文件目标时，文件集内部互为参照输入）

- **口径漂移**：同一概念两处定义 / 术语用法不一致。统一到参照输入的 SSOT 版本，另一处改引用
- **内容重复**：本文与参照文档逐字 / 逐段重复。删重复段，改为指向 SSOT 的引用
- **事实冲突**：数据 / 结论与参照文档矛盾。指出冲突双方位置，请作者裁定谁为准，改另一处
- **上下文重复定义**：已在 SSOT 定义过的概念又展开重述。一句话引用 + 链接，不重写定义

## 指令文档（被审对象是 agent 指令时启用）

适用对象：SKILL.md / AGENTS.md / system prompt / rules 文件 / CLI 工具说明。读者是执行中
的 agent 而非人。判据是 agent 读者版：冗余从"读者有损失吗"变成"**删掉这句，称职 agent
会做错吗？不会就删**"。

- **agent 通识复述**：把 agent 本就会的操作逐步铺开 / 复述通识概念 / 一行命令能替代的写成
  整段散文。删或替换为一行命令；只保留 agent 不可能知道的（私有格式、环境怪癖、踩过的坑）；
  成片出现按 冗余重复 判
- **疤痕组织**：为单次历史失败打补丁（"别忘了 X"式防御句）/ 预先回应假想误读。删（没来自
  实际失败的补丁 = 无依据）；确有护栏必要改写成正面规则一句
- **禁令无 why**：NEVER / ALWAYS 堆叠且无理由句。补"为什么"（agent 依理由而非词强遵从）；
  补不出理由的禁令大概率本就该删（常与 疤痕组织 同现）
- **时间性信息内联**："自 v2 起删除了 X"等演进史写进规范正文（agent 会把旧行为当成可选路径）。
  演进叙事移 git commit / CHANGELOG，正文最多留一句路标（外部依赖版本约束如"Python ≥ 3.7"照写）
- **决策点 N 等价选项**：≥ 3 个等价选项不给推荐。1 个推荐 + 1 个 escape hatch，其余收进
  "何时才选它"一句限定
- **示例堆叠**：同一要点配多个平庸样例（模板填空 × N、多语言各写一遍）。留一个最相关的完整
  示例（与 详略与范围 的举例条分工：那里管内联列举，本条管块级示例）
