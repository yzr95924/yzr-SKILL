# 多模型评审编排

机制铁律：票一律由 harness subagent 产生，不起 CLI 子进程；用户显式要求多模型即构成逐票指定 model 的授权。

## 名单

默认：

- yzr-dashscope/qwen3.8-flash
- yzr-dashscope/deepseek-v4.1-flash
- yzr-zai/glm-5.3-flash

- 点名覆盖默认：模糊名用 harness 模型发现解析成精确 ID，多候选让用户挑，解析不到如实报告相近候选
- 未点名：直接用默认名单不再确认，spawn 前宣布名单与票数
- spawn 前逐票校验可发现且 active；失效停下报告相近候选，交用户裁定，不静默替换、不静默减票

## 编排

1. 物化：粘贴文字先写成临时目录快照文件；磁盘文件用原路径
2. 扫描：从 skill 根跑 `python3 tools/scan_fingerprints.py <对象> --json`，输出存临时目录；编排者只跑一次，各票共享
3. spawn：一票一模型，一条消息并行发起全部票。逐票 prompt 全同，组成：角色句“你是 N 名独立评审员之一，
   只读下方材料清单列出的文件，回复正文直接产出最终评审”；对象说明（不转述主对话里的用户评价，避免锚定）；
   绝对路径清单（被审对象全文、扫描候选、SKILL.md，只按[规则集](../SKILL.md#规则集)判）。票间唯一差异是 model
4. 编排者不亲自出发现（上下文与评审员不对称）；会话模型在名单内照常入票
5. 每票审全文，不分段
6. 回退：无 model 指定能力或读盘不可用时如实退回单模型；部分票失败用余票照常合并、逐票披露状态，不凭记忆补发现

## 评审员契约

随材料清单送达各票：

- 单轮：不与用户交互，回复即交付物；只读清单内文件，不跑命令
- 产物按序：理解复述（2-4 句：在说什么、逻辑怎么走，拿不准标“存疑”）；发现清单每条一行 `- <file>:<line> | <规则名> | <问题> | <建议>`，规则名限规则集收录；不报告项（可选）
- 引用原文逐字，不翻译、不转写

## 合并

1. 逐票核对契约（有复述段、发现行格式对、行号属实），不合的如实披露不强行解析
2. 复述明显跑偏的票降权：发现不计共识、保留时标注；重跑只征询用户
3. 归并：同位置同规则名且指向同一问题的并成一条记来源集合；拿不准不硬并，宁可留两条
4. 呈现：共识（≥2 票）排前，单票附【仅 X】；同位置互斥处置单列“分歧”交用户，可给倾向不擅自裁决；
   映射不到规则集规则名的不进清单
5. 有效票仅 1 时声明“退化为单票”，清单直接进报告，不分组不标来源
