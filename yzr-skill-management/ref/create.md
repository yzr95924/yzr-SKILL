# 创建工作流

1. 素材两来源：当前对话（抽用到的工具、步骤顺序、用户做过的修正、输入输出格式），
   或被重做的旧 skill 目录（旧正文作反面参照、tools / assets 是已验证资产、旧 evals 是用例素材；
   旧执行原则逐条给处置：以原文逐条核对，不凭摘要与记忆；吸收 / 改写 / 弃用，弃用须给理由）；
   先抽取再补缺口。问清并记录每个答案落进哪一节：让 agent 能做什么、
   用户会说什么话触发归 description 关键词；期望交付什么归 `输入与输出`；不管什么、与相邻 skill
   怎么分工归 description 不适用行；流程中哪些步骤是机械的（零判断、可枚举）归 tools/ 候选。
   范围与候选清单交用户确认，确认前不写正文
2. 裸跑：不带 skill 实跑 2-3 个典型 prompt，
   指令模板见 `ref/qualitative-loop.md`；逐字记录 agent 漏做了什么、以及它的借口（原样摘抄，不预写假想借口）。重做场景先对同一素材
   实跑一次现有工具作对照基线，裸跑记录与其对比差值。按失败类型定写法：
   知道该做却找借口绕开的，写成禁令，把它当时的借口原话写进去；想做不会做的，
   写成照着跑就行的步骤；有现成工具但不知道用的，写明一律从这个入口走
   （不然它自己另造一套，同样的活干出五花八门的结果）；不知道去哪找的，写成参考资料。
   裸跑记录是正文规则的出处
3. 跑 `python3 yzr-skill-management/tools/skeleton.py new <name>` 生成骨架；重做场景跳过 new（目录已存在），
   原位替换正文，tools / assets 沿用为默认。frontmatter 按模板槽位填，
   description 按"description 写法"；正文按"节内容边界"填写，**每写一段就与用户确认一段**
   （一段 = 一节或节内若干条；用户显式授权可豁免：分段写完一次性整体交审，返工与取证记录照记）。
   素材里抽出的 tools/ 候选此时逐条定夺：按"机械活脚本化"算代价账。
   context 节省乘使用频率，是否高于脚本行数 + 冒烟维护成本；决定留在正文里的，记一句为什么
4. 定性测试：先读 `ref/qualitative-loop.md`。用例 prompt 用用户真实会说的话，从裸跑的 2-3 条
   起步，先交用户确认再跑；每条带客观可核验的期望，写入 `eval/evals.json`。subagent 实跑：
   行为测试按协议以正文内联法执行；description 草案以触发正负例判激活面；对照期望逐条判断，
   按结果修改正文并重跑，直到通过且用户满意；
   稳定通过后，再加几条相邻的、不该触发的说法测一轮，防止 description 变成什么都能套
